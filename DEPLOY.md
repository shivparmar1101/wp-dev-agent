# Deploying WP Dev Agent

Split deployment — this is the setup that works with the current architecture:

```
Netlify  ->  Next.js frontend      (https://<site>.netlify.app)
Render   ->  FastAPI backend       (https://<svc>.onrender.com)
```

Why split? The backend needs Python + a long-running process + SQLite on disk.
Netlify serves static/serverless only, so it cannot host FastAPI.

> **Data caveat:** Render's *free* tier has an ephemeral filesystem. Scans,
> sessions and search indexes survive until the next redeploy/restart. Mount a
> persistent disk (Render paid) and keep `DATABASE_URL` pointing at it if you
> need durability.

---

## 1. Backend on Render

**Render dashboard → New → Blueprint → select this repo.** Render reads
[`render.yaml`](render.yaml) automatically.

| Setting | Value |
|---|---|
| Root directory | `.` (repo root) |
| Build | `pip install -r requirements.txt` |
| Start | `python -m uvicorn backend.main:app --host 0.0.0.0 --port $PORT` |
| Health check | `/api/health` |

Then set these environment variables (marked `sync: false` in the blueprint):

| Variable | Example |
|---|---|
| `FRONTEND_URL` | `https://<site>.netlify.app` |
| `BACKEND_URL` | `https://<svc>.onrender.com` |
| `GITHUB_CLIENT_ID` | from your OAuth app |
| `GITHUB_CLIENT_SECRET` | from your OAuth app |
| `GITHUB_REDIRECT_URI` | `https://<svc>.onrender.com/api/auth/callback` |
| `AI_PROVIDER` | `gemini` |
| `AI_API_KEY` | your Gemini key |

`SECRET_KEY` is generated by Render (`generateValue: true`).

### GitHub OAuth app

GitHub → Settings → Developer settings → **New OAuth App**:

- **Authorization callback URL** must equal `GITHUB_REDIRECT_URI` **exactly**.
  Mismatch = `The redirect_uri is not associated with this application`.

### Cross-site cookies (already handled)

Frontend (`netlify.app`) and API (`onrender.com`) are different sites, so the
browser only sends the session cookie if it is `SameSite=None; Secure`.
`render.yaml` sets `SESSION_COOKIE_SAMESITE=none`, and the backend forces
`Secure` whenever `samesite=none`. Without this every request 401s after login.

CORS allows whatever you put in `FRONTEND_URL` (comma-separate several origins,
e.g. `https://site.netlify.app, http://localhost:3000`).

## 2. Frontend on Netlify

**Netlify → Add new site → Import an existing project → this repo.**

[`netlify.toml`](netlify.toml) sets base `frontend`, `npm run build`, Node 20,
and the Next.js runtime plugin. Set one environment variable:

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | `https://<svc>.onrender.com` (no trailing slash) |

Baked at build time — changing it requires a rebuild/redirect deploy.

---

## 3. Verify

```bash
curl https://<svc>.onrender.com/api/health
# {"status":"ok", ..., "github_configured":true, "ai_provider":"gemini"}
```

Then in the UI: sign in with GitHub → Repositories → scan a repo (or paste a
website URL on the *Scan a website* card).

### Render free-tier cold starts

The service sleeps after ~15 min idle, so the first request takes 30–60 s.
Sign-in and the first scan are the usual victims — retry once.

---

## 4. Local development (unchanged)

```bash
uvicorn backend.main:app --port 8000     # from repo root
cd frontend && npm run dev               # http://localhost:3000
```

`.env` + `frontend/.env.local` keep the localhost defaults; nothing in this
guide changes how the app runs on your machine.
